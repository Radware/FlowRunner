## v1.5.0-beta.1 — prompt-effectiveness eval (60 real on-device generations, blind-judged)
Ran a controlled system-prompt matrix on the ACTUAL Gemma 4 E2B: 5 variants (current baseline verbatim + role-expert + rules-first + few-shot + quality-checklist) x 12 fixtures across all 4 task families, auto-graded by the app's own validators, quality-scored by 3 blind judges (eval/ harness kept in-repo).
- **Finding: the minimal baseline SYSTEM prompt WON.** Longer/cleverer system prompts made the 2-5B grammar-constrained model worse (bare `body.`-less targets, empty-array refusals). SYSTEM_BASE stays verbatim.
- **Finding: example-anchoring is causal.** An inline example steers operator choice and value shape almost verbatim — so micro-examples moved into the per-task USER prompts (assertions, extractions) where each task picks the right example.
- **Applied fixes (all evidence-backed):** `minItems:1` on suggestion arrays (grammar forbids empty-array refusals); deterministic `body.`-prefix auto-repair for bare assertion targets (the dominant failure — repaired when the prefixed path resolves on the real response, saving the retry); 3-digit status-value guard ("?:403" → "403"); condition prompt rules (bare literal values — never ">50"; HTTP outcomes → numeric status codes); dynamic GRAMMAR ENUM of the flow's variable names in NL→condition when ≤20 vars (undefined variables become impossible to emit).
- **Ranked next methods (documented for the beta period):** dynamic few-shot from the user's own accepted suggestions; prewarm the model when a response arrives; accept/reject + repair-rate counters as a live quality signal; task→model routing (Qwen3-4B structured / Gemma prose) on ≥16GB machines; ground NL→condition with the last run's status + variable values.
- Jest 509/509. Caveat: single-model single-quant eval; rerun the matrix before routing decisions.

## v1.5.0-beta.1 — the AI Copilot (opt-in, fully local) — branch beta/1.5-local-ai
An optional local language model inside FlowRunner: helps AUTHOR and UNDERSTAND flows; the engine still RUNS them (small models are grounded helpers, not agents). Everything is opt-in, on-device, offline after one model download — nothing ever leaves the machine.
- **Engine (`llmService.js`, main process only):** node-llama-cpp v3.19 (prebuilt Node-API binaries per platform — NO MSVC/node-gyp/electron-rebuild; renderer use would crash, hence main-only). Lazy import (zero startup cost when off), models download on enable into userData/models via the built-in resumable downloader (progress → IPC), one-generation-at-a-time queue, model auto-unloads after 5 idle minutes, teardown on quit. Windows forces CPU (`gpu:false`) because the beta packages CPU binaries only; mac gets Metal via auto.
- **Consistency spine:** structured tasks decode under a JSON-SCHEMA GRAMMAR (greedy/temp-0, repeatPenalty off, maxItems/maxLength bounds) + code-side semantic validation against the app's frozen operator vocabularies + one repair retry that feeds the validation error back; suggested paths must RESOLVE against the step's real last response or they're dropped. Response bodies are pruned to a deterministic shape skeleton before prompting. Prose tasks stream (abortable) at temp 0.6.
- **Model catalog (all Apache 2.0, ungated GGUFs):** Gemma 4 E2B (default, ~3.1GB), Qwen 3 4B Instruct (structured fallback, ~2.5GB), Gemma 4 E4B (quality, ~5GB, 16GB-RAM machines). Qwen3-1.7B was CUT after the live harness showed its hybrid-thinking mode leaking `</think>` garbage INTO grammar-constrained string fields.
- **Features (beta set):** Explain result (streamed, on any result row), run Digest, Suggest extractions + Suggest assertions from the step's real response (fill the existing editors as reviewable rows — the copilot never saves), NL→condition ("describe it" box in the condition builder), step naming, flow description. All affordances gate on `html.ai-ready`; the surface stays projector-clean when off; browser mode shows a desktop-only note.
- **Harness-caught bugs (why we test with real weights):** (1) per-request session/sequence dispose leaked sequence slots → "No sequences left" on the 2nd request — fixed with ONE persistent session per loaded model, reset via `setChatHistory` per request (also lets each task swap its system prompt); (2) the Qwen thinking leakage above.
- **Packaging:** asarUnpack for node-llama-cpp bins (native binaries cannot load from inside app.asar; the sidecars are .dll/.dylib so `**/*.node` globs are NOT enough), `${os}-${arch}*` binary globs with explicit `-vulkan/-cuda` excludes (Windows CPU-only ≈ 44MB instead of ~300MB), three new modules in build.files. Verified template: node-llama-cpp's official electron-builder config.
- **Tests:** 15 unit tests (validators/skeleton/path-resolution) + 6 Electron e2e (real preload bridge, IPC round-trips, modal, gating, clean no-model failure). Real-inference harness run on-device against Qwen3-1.7B and Gemma 4 E2B (whose assertion suggestions came back flawless: status equals 200, body.title is_not_empty, …).

- **Scope:** 6 new renderer modules (all in build.files), fs:scanFlows IPC, edits to fileOperations/eventHandlers/uiUtils/index.html/styles.css, listSelection unit tests. Jest 492/492, e2e 20/20. ## v1.3.0 — release round: final bug sweep (18-agent panel, 11 distinct confirmed findings, all fixed)
- **[HIGH] Flow-format round-trip corruption (pre-existing since v1.0):** loading a flow decoded `##VAR:unquoted:x##` body markers to a QUOTED `"{{x}}"` in the editor text, so the next save silently re-classified them as string markers — `{"id":{{n}}}` became `{"id":"{{n}}"}` and the request's JSON types changed (breaking strict APIs and the shared CLI contract). New `stringifyBodyForDisplay()` renders unquoted markers bare; regression test locks the round-trip.
- **[HIGH] Runs board re-rendered on EVERY engine event** (hundreds/sec at 0ms delay): window-wide jank, and Stop/Remove buttons destroyed between mousedown and mouseup — clicks eaten, runs unstoppable. Renders now coalesce (≥250ms apart) and defer while a pointer is held down in the list. Validated live: a real mouse click stopped a ~500-iterations/sec run at #3032.
- **Background-run tallies dropped the final iteration on user stop:** iterations were closed lazily on the NEXT onIterationStart, so stopping in the between-iterations window (the common case) under-counted by one. New additive engine callback `onIterationComplete` closes iterations eagerly; validated live (chip #23 → "23 iterations · 23 passed").
- **Quit silently killed live background runs:** the quit/close guard predicate ignored them (only foreground state counted); now includes `hasLiveBackgroundRuns()`, plus `stopAllBackgroundRuns()` on beforeunload aborts in-flight fetches.
- **Enter in a confirm dialog always confirmed** even when the danger-dialog focus sat on Cancel — Enter now activates the focused button.
- **One Ctrl/Cmd+Z fired BOTH undos** (flow-model + Tidy-Up layout) in graph view — layout undo now takes precedence when available.
- **Undo/redo with the node-editor modal open left a stale editor** — render() now closes it if the step vanished and refreshes it when clean (dirty edits stay).
- **Condition preview injected unescaped user text** into the List-view card (`<`/`>` broke or injected HTML) — escaped, matching the graph view.
- **Import cURL: unknown value-taking flags ate the URL** (`--connect-timeout 5` imported a request to "5") — known-flags list extended + bare tokens must look like a URL.
- **The X on a flow filed in a folder did nothing** (removed from recents, re-rendered from the workspace) — it now also removes the flow from the workspace/folder.
- **validateFlow rejected dotted loop sources** (`{{resp.items}}`) that the runtime executes fine — only the base variable must be defined now.
- Deterministic pre-release check: renderer import graph (38 modules) vs `build.files` — complete; CI island build verified coherent.

## Unreleased — Per-step assertions + run test-summary (UX Wave 3, lane assertions)
- **Decision:** added an **additive optional** `step.assertions` = `[{ target, operator, value, critical? }]` on **request** steps. Each assertion is checked against the step's result **after** it runs and **NEVER changes request execution** — it only annotates the result and (optionally, per a `critical` flag) requests a stop. **Targets:** `status`, `duration` (ms), `headers.<name>`, `body.<path>` (dotted/array paths). **Operators reuse the frozen `conditionData` vocabulary** — evaluation goes through the existing `evaluateCondition` + `evaluatePath` (in `executionHelpers.js`), so the CLI can evaluate the same files with its existing operator set (cross-app safe). **Why:** highest-value new capability that reuses existing engine data, stays additive, and needs no new JS engine on the Python side.
- **Evaluation (`executionHelpers.js`):** new pure `evaluateAssertions(assertions, output, durationMs)` → a test-summary `{ total, passed, failed, allPassed, criticalFailed, results[] }`, plus `buildAssertionSubject(output, durationMs)`. **Subject/path subtlety:** `evaluatePath` dives into `data.body` for prefix-less paths, so bare `status`/`duration` are evaluated against a **body-less mini-subject** (see `resolveAssertionTarget`) while `headers.*`/`body.*` use the full subject — this is the one non-obvious bit. Unknown/newer operators degrade to a **failed** assertion (never throw), matching the tolerant-reader stance; a genuine eval error is caught and reported as failed, never aborting the run.
- **Runner wiring (`flowRunner.js`):** `_executeRequestStep` now stamps an additive `duration` (ms) onto the request `output`. `_executeSingleStepLogic` calls `_evaluateStepAssertions(step, result)` after a request (only when it produced output), attaching `result.assertionSummary`. The evaluator is **injected** as `evaluateAssertionsFn` (defaulted in `createFlowRunner`) to avoid a `flowRunner`→`executionHelpers` import cycle — an unset evaluator = identical legacy behavior (existing `new FlowRunner({...})` call sites, incl. the test harness, don't evaluate assertions).

## Unreleased — Per-request retries/backoff + cURL/HAR import (UX Wave 2, lane engine-features)
- **Decision (retries):** `_executeRequestStep` in `flowRunner.js` now honors an **additive** request-step field `step.retries = { count, delayMs }`. A retry fires on a **non-2xx HTTP status OR a network/fetch error**, up to `count` times, sleeping `delayMs` (via the existing `_sleep`, which short-circuits on `stopRequested`) between attempts. Default is `count: 0`, which is **byte-for-byte the previous single-attempt behavior** — the `onFailure` (`stop`/`continue`) semantics are unchanged and only apply once retries are exhausted. A **user-requested stop/abort is never retried**. ## Unreleased — Auto-layout foundation (spike + engine-agnostic adapter)
- **Decision (spike):** ship **elkjs** for flow-graph auto-layout via its **bundled build run on the main thread** (`import ELK from 'elkjs/lib/elk.bundled.js'`, no `workerUrl`). **Why:** FlowRunner's renderer CSP is `script-src 'self'` with **no `worker-src`** (falls back to `script-src`) and **no Node integration** (`contextIsolation:true`), so a `blob:`-URL Web Worker (how most bundlers ship ELK) would be **blocked**, and the Node `web-worker` path is unavailable. The bundled build's inlined **synchronous "fake worker"** touches none of the CSP-restricted primitives (`Worker`/`Blob`/`importScripts`) — the only unconditionally CSP-clean path without relaxing the policy. Flows are small (tens of nodes), so main-thread layout is single-digit-ms; a real worker buys nothing and would need a same-origin worker file plumbed through `build.files`. Full findings + the future same-origin-worker escape hatch in [docs/auto-layout-spike.md](docs/auto-layout-spike.md).
- **New module `autoLayout.js`:** engine-agnostic adapter, **not yet wired into `flowVisualizer.js`** (Wave 2 adds a "Tidy Up" button). `computeLayout(steps, { engine, nodeSizes, direction })` → `{ positions: { [stepId]: {x,y} }, engine }`. Input respects then/else/loop nesting and accepts **both** the in-memory model shape (`thenSteps`/`elseSteps`/`loopSteps`) and the on-disk `.flow.json` shape (`then`/`else`/`steps`). Uses ELK **layered + `hierarchyHandling:INCLUDE_CHILDREN` + orthogonal edge routing**; output is flat, top-left, origin-normalised, **deterministic** (stable document-order feed + fixed spacing).
- **Fallback engine:** **`@dagrejs/dagre`** (pure-JS, synchronous, equally CSP-clean). Used when ELK throws or when `engine:'dagre'` is requested; result reports which engine actually ran. Dagre reports node centers — adapter converts to top-left.
- **Deps + build.files:** added `elkjs` and `@dagrejs/dagre` as `dependencies`; added `autoLayout.js` to `build.files` now (per the #1 rule) so it's packaged the moment Wave 2 imports it.
- **Tests:** `__tests__/autoLayout.test.js` — 21 TDD cases (graph-in → positions-out; linear/branches/nested loop+condition; both field-name shapes; determinism; node-size respect; engine fallback) run against **both** engines. Suite: 126 → **147 passing**.
