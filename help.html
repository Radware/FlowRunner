FlowRunner Help

Introduction

Welcome to FlowRunner! This application allows you to visually create, manage, run, and debug sequences of API calls (known as "Flows"). It's designed for tasks like demonstrating API interactions, testing multi-step processes, and understanding data flows.

Flows are saved locally as .flow.json files. You can work entirely offline for authoring and visualization; network access is only needed when executing API Request steps that target external endpoints.

Getting Started

Here's a quick way to run your first flow:

  1. Click "+ New Flow" in the Flows drawer on the left.
  2. Press Tab (or click "+ Add Step") and choose "API Request".
  3. In the request bar, set the URL to https://httpbin.org/get (leave the method on GET), then click "Save Step".
  4. Click the green "▶ Run" in the top bar (or press F5).
  5. Watch the step highlight, then open the Results tab on the right for the response from httpbin.
  6. Save the flow with Ctrl/Cmd+S. It becomes a portable .flow.json file.

Interface Overview

FlowRunner is one window with a few fixed zones.

The rail (far left)

  • Toggle the Flows drawer, open the command palette (Ctrl/Cmd+K), jump to the Runs page, switch theme, and enter Present mode. A badge on the Runs button counts live background runs.

The top bar

  • Flow name and an UNSAVED marker; Save (brand-blue when you have changes), plus copy, undo/redo, and export controls.
  • List / Visual switch for the workspace, and an ambient engine-status dot.
  • Run cluster (right): Step, Stop, Background, and the single accent Run. The run verdict (Passed / Failed / Running) reads here at projector scale.

The Flows drawer (left)

  • Your flow library: Recent files plus folders and subfolders you arrange yourself (drag a flow onto a folder). New Flow, Open, Import cURL, and Import HAR live here.
  • Select mode (the checkbox toggle) reveals checkboxes so you can pick several flows at once and run them in the background together. Shift-click for a range; right-click a flow for its menu.

The workspace (center)

  • The flow itself as either the List editor (dense, configuration-first, drag the ☰ handle to reorder) or the Visual node graph (structure at a glance; drag nodes, zoom, minimap, Tidy Up).

The inspector (right)

  • Results: the run feed, one scannable line per request (name, method, HTTP code, duration, verdict), expandable to full output, extracted values, and warnings. Search, filter, copy, or export to JSON/CSV. Run controls (Continuous, Delay, Clear) live at the top.
  • Variables: everything defined and extracted, with where each came from.
  • Config: flow name, description, global headers, and static variables.
  • Use the expand control in the inspector header to widen it into a roomy work surface for Variables and Config.

The Runs page

  • Open Runs from the rail for the full background-run board: each run's verdict, iteration and pass/fail tallies, a streaming feed, and Stop / Remove. Click New background run to launch one or many flows from a searchable picker.

Core Concepts

Flows

A Flow is a sequence of steps saved as a single .flow.json file. You can configure overall flow settings in the Config tab of the inspector (right):

  • Name & Description: Basic identification.
  • Global Headers: Headers automatically added to all API Request steps (can be overridden by step-specific headers).
  • Flow Variables (Static): Key-value pairs defined once and available throughout the flow execution context. Each variable can be typed as String, Number, Boolean, or JSON. Values may be JSON arrays or objects for loops or complex data.

Steps

Flows are built from individual steps. Configure steps by selecting them in the List/Editor view and using the editor panel on the right.

  • API Request: Makes an HTTP call. Configure Method, URL, Headers, Body (JSON), Extraction rules, and On Failure behavior (Stop/Continue). Use Copy cURL to generate a command with resolved variables when available.
  • Transform: Performs ordered operations to compute or modify variables (base64, JWT, math, JSON updates) without custom scripting.
  • Condition (If/Else): Executes different branches (Then/Else) based on evaluating a variable against a value using an operator. Add steps to branches via the '+ Add Step' buttons inside the condition step in the List view.
  • Loop (For Each): Repeats a sequence of steps (the Loop Body) for each item in a source array variable. Defines an 'Item Variable' (e.g., item) accessible within the loop body. Add steps to the body via the '+ Add Step' button inside the loop step in the List view.

Example: Define a JSON variable userList in the Flow Info overlay:

[
    { "name": "Alice", "active": true },
    { "name": "Bob",   "active": false }
]

Create a Loop step with source {{userList}} and item variable user. Within the loop body reference {{user.name}} or add a Condition step checking user.active.

Variables

  • Definition: Variables hold data during flow execution. They can be:
    • Static: Defined in the Config tab.
    • Extracted: Created/updated by 'Extract' rules in API Request steps from the response (status, headers, body path).
    • Loop Item: Automatically created within a Loop step to hold the current item.
    • Runtime: (Not directly definable by user) Variables modified during execution, including Transform outputs.
  • Substitution: Use {{variableName}} syntax to insert variable values into URLs, Header values, Request bodies, Condition values, and Loop sources. The runner replaces this at execution time.
  • Special Variables: {{RANDOM_IP}} generates a random public IP once per flow run. {{RANDOM_INT(1,1000)}} generates a random integer. {{RANDOM_STRING(16)}} generates a random alphanumeric string.
  • Insertion Helper ({{…}}): Click this button next to input fields to get a searchable list of currently defined variables and insert them easily.
  • Variables tab: Open the Variables tab in the inspector to see every variable the flow's structure defines (Static, Extract, Loop) and where each originates. This shows what is defined, not live runtime values.
  • Full Body Extraction: Use body as the JSON Path in an API Request step's Extract tab to store the entire response body for that step.

Views

  • List/Editor View: Default view showing steps hierarchically. Best for detailed configuration using the step editor panel. Supports step reordering via drag-and-drop using the ☰ handle and step search for quick jumps.
  • Node-Graph View: Visual representation of the flow structure with connecting lines. Useful for understanding branching and looping. Pan by dragging the background. Drag nodes to rearrange the visual layout (positions are saved with the flow). Select nodes by clicking them. Use zoom controls and the minimap to navigate large graphs, or Tidy Up to auto-arrange.

Background Runs

A background run executes a snapshot of a flow independently, so it keeps going while you keep authoring, and later edits never disturb a run already in progress. Launch one from wherever you are:

  • The flow you're editing: the Background button in the top run cluster. A quick popover confirms Continuous and Delay, then it runs from your current (even unsaved) state.
  • Several at once: turn on Select mode in the Flows drawer, tick the flows, and run the set together.
  • From a large library: open Runs on the rail and click New background run for a searchable picker that scales to thousands of flows (point it at a folder to search them all).

Live runs appear as chips in the top bar and a badge on the rail; the Runs page shows the full board (verdicts, tallies, streaming feeds, Stop / Remove).

Present mode

Press the presentation icon on the rail (or Ctrl/Cmd+Shift+D) for a full-screen, projector-tuned view: bigger type, bolder run state, and less chrome, for showing a live flow to a room.

Troubleshooting

  • Windows Installer Warning: Windows SmartScreen may warn about the unsigned app. Click "More info" then "Run anyway".
  • macOS "Damaged" Error: If macOS prevents opening, run this in Terminal: xattr -c /Applications/FlowRunner.app (adjust path if needed), then try opening again (possibly right-click > Open).
  • Save/Load Issues: Check file permissions. Ensure the .flow.json isn't corrupted. Look for error messages in the UI.
  • Request Step Fails: Verify URL, Method, Headers, Body (use Format button for JSON). Check the Runner Results panel for status codes or network errors. Check the step's 'On Failure' setting.
  • Variable Issues: Check spelling in {{varName}}. Ensure variable is defined *before* use (Static, previous Extract/Loop). Use the Variables Panel and the {{…}} helper. Check Extraction warnings in the Results panel.
  • Condition/Loop Issues: Verify logic and source variables in the step editor. Check variable values from previous steps in the Results panel.
  • General/UI Issues: Restart FlowRunner. Use the Developer Tools (View > Toggle Developer Tools) and check the 'Console' tab for errors.
